# Day 30 — Supply Chain Builder (AI-Powered Simulator)

## What I Built
A single-file HTML + React application called **Supply Chain Builder** — an interactive, beginner-friendly simulator that teaches supply chain fundamentals through hands-on decision-making.

The entire app (UI, logic, styling, animations) lives in **one HTML file**, runs **fully offline**, and uses **React + Babel via CDN** with no backend, no APIs, and no build tools.

## How It Works
1. **Welcome screen** — explains what a supply chain is in plain language, with a visual flow: Supplier → Factory → Warehouse → Transport → Customer.
2. **Random company generator** — every playthrough creates a new company (industry, products, regions served, demand pattern).
3. **Five guided decisions:**
   - Supplier strategy (single / multiple / local + backup)
   - Factory location (domestic / nearshore / offshore)
   - Warehouse strategy (central / regional / 3PL)
   - Transportation method (road / rail / sea / air)
   - Inventory strategy (low / balanced / high)
4. **Before every choice**, the app explains the concept, why it matters, and the trade-offs in plain English — no jargon.
5. **Live business metrics** update instantly after each decision: Cost, Delivery Speed, Risk, Customer Satisfaction, Sustainability.
6. **Final dashboard** generates an Overall Supply Chain Score (0–100), strengths, weaknesses, biggest risk, and three practical, personalized recommendations.
7. **Replay button** generates a brand-new random company for unlimited practice.

## Tech Stack
- React 18 (CDN)
- Babel Standalone (in-browser JSX compilation)
- Pure CSS (dark theme, rounded cards, hover states, animated progress bars, sticky side panels)
- Zero dependencies, zero backend — opens directly in any browser

## Key Learnings
- **Prompt precision matters.** Specifying "single HTML file, React via CDN, no Tailwind/npm/backend" up front avoided a multi-file scaffold that wouldn't run offline.
- **Trade-offs are the real lesson.** Every supply chain decision (e.g., offshore factory = cheaper but slower and riskier) needed an explicit, opposing pair of effects on the metrics — this is what makes the simulation actually *teach* something instead of just being a clicker.
- **Randomization adds replay value.** Generating a new company each run (industry, regions, demand pattern) turns a one-time demo into a tool people can use repeatedly to build intuition.
- **Score design needs nuance.** Risk had to be inverted (lower risk = higher stability) before averaging into the overall score, otherwise the math would reward risky chains.
- **Small UI details compound.** Animated bar fills, hover lifts on option cards, and a progress-pip tracker made a static decision tree feel like a real interactive dashboard.
