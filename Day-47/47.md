# Day 47 — Content Intelligence Studio

**#100DaysOfGenAI · Building AI-powered apps with Claude**

## What I built

A single-page **Content Intelligence Studio** — an AI content consultant that reviews social posts through a multi-stage pipeline of specialized reviewer personas, each calling the Claude Messages API live (no backend, no key stored, no hardcoded scoring).

For this run I configured it for:
- **Content type:** LinkedIn post/caption
- **Goal:** Maximize engagement
- **Inputs:** Post text + analytics screenshot
- **Review style:** Balanced / professional

## The pipeline

1. **Hook & Opening Line Reviewer** — scores the first two lines against what actually earns a "see more" click
2. **Structure & Readability Reviewer** — line-break rhythm, scannability, dwell-time friendly formatting
3. **Engagement Psychology & CTA Reviewer** — relatability, emotional resonance, comment-bait vs. genuine engagement
4. **Analytics Performance Reviewer** — reads the analytics screenshot directly with Claude's vision, interprets real numbers against LinkedIn benchmarks
5. **Algorithm & Platform-Fit Reviewer** — early-engagement window, dwell time, hashtag hygiene, distribution mechanics
6. **Chief Content Strategist (Synthesis)** — weighs all five findings into one final report: exec summary, health report, top improvements, an explicitly-labeled AI performance estimate, a full rewrite, alternative hooks, a publishing checklist, and follow-up prompts

## Tech stack

Vanilla HTML/CSS/JS, single self-contained file. No frameworks, no external libraries. Calls `https://api.anthropic.com/v1/messages` directly from the browser using `claude-sonnet-4-6`.

## Key learnings

- **Ditching JSON saved me from a whole category of bugs.** Instead of asking Claude to return JSON (which reliably breaks with stray commas, markdown fences, or trailing text), I designed a plain-text `===SECTION===` tagging protocol. A simple regex extracts every section, no `JSON.parse` in sight, no "Unexpected token" errors.
- **Multiple small specialist prompts beat one giant prompt.** Splitting the review into 6 focused reviewer personas (each with a tight, single-purpose system prompt) produced sharper, more specific feedback than asking one prompt to "review everything at once."
- **Vision works the same way text does.** Feeding the analytics screenshot as a base64 image block to a vision-capable model meant the "Analytics Performance Reviewer" could read real numbers off a screenshot rather than me having to transcribe them.
- **Progressive UI reveal matters for perceived quality.** Rendering each reviewer's card as soon as its call resolves (instead of waiting for the whole pipeline) made a 6-call sequential flow feel responsive instead of like a long spinner.
- **Retry logic per-stage, not per-pipeline.** If stage 4 fails, the user shouldn't have to re-run stages 1–3. Isolating retries to the failed stage kept the UX honest about where things broke.
- **Design tokens before code.** Picking a deliberate palette/type system upfront (an "analyst's desk" identity — ink and paper tones, a serif/mono pairing, an instrument-style score dial) kept the UI from defaulting to generic AI-tool styling.
