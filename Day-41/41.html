Module 1 of 4 · Foundational

Variables & Data Types

Every program is, at its core, a machine for remembering things and doing arithmetic (broadly defined) on what it remembers. Variables are how JavaScript remembers.

1.1

Declaring variables: var, let, const

JavaScript has three keywords for creating a variable, and they were not all introduced at the same time. var has existed since 1995. let and const arrived in 2015 (ES6) specifically to fix problems with var. In modern code you should reach for const by default, let when you know the value will change, and avoid var entirely unless you're reading legacy code.

variables.jsES6+
const siteName = "Learning Studio";   // cannot be reassigned
let score = 0;                      // can be reassigned
score = score + 10;
var legacyCounter = 1;             // works, but avoid in new code
AnalogyThink of a variable as a labeled storage box. const is a box that gets sealed shut the moment you put something in it — you can look inside, but you can't swap the contents. let is a box with a lid you can open and refill as often as you like. var is an old warehouse crate that, confusingly, can sometimes be reached from a completely different room of the building — which is exactly the kind of surprise that gets programs into trouble.
KeywordReassignableRedeclarableScopeHoisting behavior
varYesYesFunction scopeHoisted & initialized as undefined
letYesNoBlock scopeHoisted but in "temporal dead zone"
constNoNoBlock scopeHoisted but in "temporal dead zone"
1.2

Primitive vs. reference types

JavaScript has seven primitive types — string, number, boolean, undefined, null, symbol, and bigint — plus one big catch-all reference type: object (which arrays and functions are special forms of). The difference matters enormously: primitives are copied by value, objects are copied by reference.

1.3

Type coercion

JavaScript is dynamically and loosely typed: a variable's type is decided at runtime, and operators will often convert (coerce) operands to make an operation "work" rather than throwing an error. This is convenient and, if you don't know the rules, a constant source of bugs.

Try it — Type Coercion Lab

Pick an expression and evaluate it to see JavaScript's actual coercion behavior, with an explanation.

// pick an expression and click Evaluate
Common misconception"== and === are interchangeable." They're not: == coerces types before comparing, === does not. Default to === unless you have a specific reason to coerce.
Common misconception"const means the value can never change." It means the binding can't be reassigned. const arr = [1,2]; arr.push(3); is completely legal — the array's contents changed, but arr still points at the same array.

Key takeaways

  • Use const by default, let when reassignment is needed, and avoid var
  • Primitives copy by value; objects/arrays copy by reference
  • === is almost always the right choice over ==
  • const prevents reassignment, not mutation
Module 2 of 4 · Building blocks

Functions

A function is a reusable block of instructions. Once you can bundle logic into functions, you stop repeating yourself and start building programs out of well-named pieces.

2.1

Three ways to write a function

functions.jsthree forms
// 1. Function declaration — hoisted, callable before it's defined
function greet(name) {
  return `Hello, ${name}!`;
}

// 2. Function expression — stored in a variable, NOT hoisted the same way
const farewell = function(name) {
  return `Goodbye, ${name}!`;
};

// 3. Arrow function — concise, inherits `this` from surrounding scope
const shout = (name) => `${name.toUpperCase()}!`;
AnalogyA function is a vending machine: you insert specific inputs (parameters), an internal process runs out of view, and a product comes out (the return value). Arrow functions are the same machine with a slimmer chassis — same product, less packaging — but with one real difference: they don't have their own this, they borrow it from whatever room (scope) they were built in.
FormHoisted?Has own this?Best for
DeclarationFullyYesNamed, reusable, top-level functions
ExpressionNo (var-hoisting only)YesConditionally defined functions
ArrowNoNo — inheritsShort callbacks, preserving this
2.2

Parameters, defaults & rest

function makeOrder(item, qty = 1, ...extras) {
  return `${qty}x ${item} with [${extras.join(", ")}]`;
}
makeOrder("Taco");                          // "1x Taco with []"
makeOrder("Taco", 3, "salsa", "lime");        // "3x Taco with [salsa, lime]"

qty = 1 is a default parameter, only used when no argument (or undefined) is passed. ...extras is a rest parameter that scoops up any remaining arguments into a real array.

2.3

Functions are first-class values

In JavaScript, functions are values just like numbers or strings — you can store them, pass them into other functions, and return them from other functions. This is what powers array methods like .map, .filter, and .reduce.

Try it — Function Pipeline

// choose steps and run the pipeline
Common misconception"Arrow functions are just shorter syntax with no real difference." They also don't get their own this, don't have an arguments object, and can't be used as constructors — these aren't stylistic, they change behavior.
Common misconception"A function expression is hoisted exactly like a declaration." Only the variable is hoisted (as undefined if var, or into the temporal dead zone if let/const) — the function body is not available until that line runs.

Key takeaways

  • Declarations are hoisted whole; expressions and arrows are not
  • Arrow functions inherit this from their enclosing scope
  • Default and rest parameters make functions flexible without overloads
  • Functions can be passed around and returned like any other value
Module 3 of 4 · Where things live

Scope & Closures

Scope answers one question: from this exact line of code, which variables can I see? Get comfortable with scope and closures stop being magic and become a tool you reach for on purpose.

3.1

Global, function & block scope

JavaScript looks a variable up starting from where it's used, then walks outward through each enclosing scope until it finds it (or runs out of scopes and throws). This chain of "ask here, then ask the parent" is the scope chain.

AnalogyScope is a set of nested rooms. Standing in the innermost room, you can see everything on the table in your room, and everything in every room outside yours, all the way out to the lobby (global scope). But someone standing in the lobby has no idea what's on the table in your room — they've never been inside it.
3.2

Closures

A closure happens when a function "remembers" the variables from the scope it was created in, even after that outer function has finished running. This isn't a special syntax — it's just how JavaScript functions always behave.

function makeCounter() {
  let count = 0;                 // private to this closure
  return function() {
    count++;
    return count;
  };
}
const counterA = makeCounter();
counterA();  // 1
counterA();  // 2 — count was remembered between calls
AnalogyA closure is a backpack. When a function is created, it packs a backpack with references to the variables around it. Wherever that function travels afterward — passed to another part of the program, called later, stored for years — it still has that backpack on its back.

3.3

Hoisting & the classic loop bug

var is function-scoped, so a var declared inside a for loop is really just one variable shared by every iteration. let creates a fresh binding per iteration. This single difference is responsible for one of the most common early JS bugs.

Try it — var vs let in a loop

Both loops schedule three callbacks with setTimeout. Toggle and run to see the difference.

// pick var or let
Common misconception"Closures only matter for advanced code." They quietly power event handlers, debouncing, memoization, module patterns, and React hooks — you're using them constantly, often without noticing.
Common misconception"Block scope applies to var too." It doesn't — var ignores { } blocks entirely and only respects function boundaries.

Key takeaways

  • Scope determines visibility; the scope chain is searched from innermost to outermost
  • A closure is a function plus the variables it remembers from its birth scope
  • let/const create a new binding per loop iteration; var does not
  • let/const exist in a "temporal dead zone" before their declaration line runs
Module 4 of 4 · Mastery & application

Control Flow

Control flow is how a program makes decisions and repeats work. Combined with variables, functions, and scope, it's the last piece needed to write real, useful programs.

4.1

Conditionals & truthy/falsy

JavaScript only has six falsy values: false, 0, "", null, undefined, and NaN. Every other value — including "0", [], and {} — is truthy.

AnalogyAn if statement is a bouncer at a club door. It doesn't check for a specific guest list; it just asks "is this truthy?" The falsy six are permanently turned away. Everything else — even an empty array, which feels like it should be "nothing" — gets waved straight in.

4.2

Loops: for, while, for...of, for...in

LoopBest forWatch out for
forKnown number of iterations, index neededOff-by-one errors
whileUnknown iteration count, condition-drivenForgetting to update the condition → infinite loop
for...ofIterating values of arrays/strings/mapsDoesn't give you an index directly
for...inIterating keys of a plain objectShould not be used on arrays
4.3

Short-circuit logic: &&, ||, ??

user.name || "Guest";        // falls back on ANY falsy value, including "" or 0
user.name ?? "Guest";        // falls back ONLY on null or undefined
isLoggedIn && showDashboard(); // only runs showDashboard() if isLoggedIn is truthy
Try it — Flow Tracer

Enter a score (0–100) and trace which branch a grading function takes.

Common misconception"|| and ?? do the same thing." || triggers on any falsy value; ?? only triggers on null/undefined — so 0 || "default" gives "default", but 0 ?? "default" gives 0.
Common misconception"for...in is the normal way to loop over an array." It iterates keys (as strings, in unspecified order for non-integer keys) and can pick up inherited properties — use for...of or .forEach for arrays instead.

Key takeaways

  • Only six values are falsy — everything else, including [] and {}, is truthy
  • Pick the loop that matches your data: index-based, condition-based, or iterable-based
  • ?? is safer than || when 0 or "" are valid values

Final practical challenge — Build a Grade Book

Combine everything: write a function gradeReport(scores) that takes an array of numbers and returns a string report. Use a const/let appropriately, a closure-based tally, and control flow for grade bands (A ≥ 90, B ≥ 80, C ≥ 70, else F). Your function should return a string in the exact form: "3 students, average 81, grades: B, A, F" (order matches input, average is rounded down with Math.floor).

Challenge editor
// write gradeReport() above, then click "Run tests"
solution.js
function gradeReport(scores) {
  const grades = scores.map(function(s) {
    if (s >= 90) return "A";
    if (s >= 80) return "B";
    if (s >= 70) return "C";
    return "F";
  });
  const total = scores.reduce(function(sum, s) { return sum + s; }, 0);
  const avg = Math.floor(total / scores.length);
  return `${scores.length} students, average ${avg}, grades: ${grades.join(", ")}`;
}
