# Day 49 — Personal AI Playbook

## Overview
Today's build was a **Personal AI Playbook**: a single self-contained HTML app that turns ad-hoc AI prompting into reusable, structured workflow systems — tailored specifically to how I use Claude day to day.

**My profile (from Claude's interview):**
- Role: Software / technical (engineer, developer, data)
- Primary use case: Writing & debugging code
- Model used most: Claude
- Experience level: Intermediate — comfortable, daily use, mostly ad-hoc prompting
- Biggest bottleneck: AI code that's *almost* right but needs a lot of fixing
- Desired outcome: Prompts that produce fewer bugs on the first try

Claude used that context to generate a fully personalized app rather than a generic prompt library.

## What I Built
A single-file HTML/CSS/JS app with:

- **Dashboard** — 7 ready-made workflows grouped into 4 categories: First-Try Precision, Debugging Systems, Code Review & Refactor, and Docs & Explainers. Each has editable variables, a live preview, best practices, and one-click copy.
- **Prompt Builder** — assembles a prompt from 9 labeled building blocks (role, objective, context, constraints, reasoning strategy, output format, tone, examples, quality checks), each with a plain-language explanation of what it does and why it matters.
- **Loop Builder** — converts any prompt into a self-checking autonomous loop by defining a goal, evaluation criteria, improvement strategy, stop conditions, and safety rules.
- **My Workflows** — full CRUD (create, edit, duplicate, favorite, search, filter) backed by `localStorage`, plus JSON import/export for backups.
- Dark mode, keyboard shortcuts (`D` / `P` / `L` / `W`, `/` to search, `T` for theme, `?` for help), a persistent explainer banner, and a permanent "What is this?" help button so the tool is legible to a first-time viewer.

## Key Learnings
- Structuring a prompt into explicit parts (role, constraints, reasoning strategy, output format) catches a lot of the "almost right" mistakes before they happen — most of them come from missing edge cases or unstated constraints, not bad logic.
- A loop only actually improves anything if you give it real evaluation criteria and a stop condition — otherwise it just repeats the same answer.
- Personalizing an AI tool by interviewing the user first (role, bottleneck, desired outcome) produces a noticeably more useful default set of workflows than a generic template would.
- Keeping everything in `localStorage` with import/export is a lightweight but effective way to make a personal tool actually persistent without needing a backend.
