Why this system prompt is shaped this way

Interlude is scoped deliberately narrow: one stressor, one technique, one session. The prompt front-loads that constraint so the model doesn't drift into open-ended therapy-style conversation, which would be both out of scope and a poor fit for someone with five minutes between meetings. A fixed six-step conversation shape keeps every session predictable without feeling scripted, and a named technique library (rather than "pick anything") keeps responses concrete and repeatable instead of generic mindfulness platitudes.

Crisis handling is written as a hard override, not a suggestion, because a wellness companion that stays in "quick breathing tip" mode during a real crisis would be actively harmful. The prompt also explicitly forbids diagnosing or claiming clinical credentials, since this is a stress-relief companion, not a therapist.


        


        

          
Design decisions

          
    
            
  • Two-panel layout: the conversation carries the emotional work; a persistent side panel holds the breathing circle so the "quick technique" promise is visible even before the person types anything — it's not just described in text, it's demonstrated.
    • 
            
  • Ambient vs. guided breathing: the circle pulses gently at all times (low-commitment, non-intrusive), and switches to a slower 4-7-8 guided rhythm with text cues only when the person opts in — mirroring how the assistant itself only offers a technique after listening first.
    • 
            
  • Warm sage + amber palette: chosen instead of a clinical blue/white pairing to feel more like a supportive colleague's office than a medical app, while amber is reserved for the one moment of real warmth — the active breathing state and the send action.
    • 
            
  • Starter chips in the empty state: busy professionals often stall on "how do I even describe this," so four concrete, recognizable scenarios lower the barrier to the first message.
    • 
            
  • Visible API key control: since this runs client-side with no backend, the key lives in memory only for the session (never localStorage) and the button always shows whether a key is set, so trust is never ambiguous.
    • 
          

        


        

          
Where this could go next

          
    
            
  • Tools: a calendar-read tool to automatically detect "you have 12 minutes until your next meeting" and tailor technique length without asking; a simple timer tool the model can trigger directly instead of relying on CSS animation timing alone.
    • 
            
  • Memory: a lightweight, user-controlled log of which techniques worked best for which stressor, so week two onward Interlude can say "last time inbox overwhelm hit, the physiological sigh worked for you — want that again?"
    • 
            
  • Multi-step workflows: an optional end-of-week reflection flow that surfaces patterns ("this is the third time a 1:1 with the same person spiked your stress") and gently suggests a boundary-setting script rather than another in-the-moment fix.
    • 
            
  • Team/manager mode: an aggregated, anonymized view for team leads showing overall stress trends (never individual sessions) to inform workload conversations.
