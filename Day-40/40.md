# Day 40 — AI Assistant Builder: Interlude

## What I built

**Interlude** — a mental wellness companion for busy professionals, designed to deliver one quick, concrete stress-relief technique per session instead of an open-ended therapy-style chat.

Built using a structured "AI Assistant Builder" prompt that interviewed me (via MCQs) on:

1. **Domain & niche** → Health & Wellness → Mental Wellness Companion
2. **Audience & outcome** → Busy professionals; walk away with a technique they can use immediately
3. **Input style** → Multi-turn conversation (a real back-and-forth check-in)
4. **Output format** → Conversational chat
5. **Tone** → Warm & friendly, like a supportive colleague

From those answers, Claude generated a production-quality system prompt and a complete single-file HTML application.

## The system prompt

The prompt scopes the assistant tightly:

- A fixed 6-step conversation shape (listen → reflect → one clarifying question if needed → one technique → guided practice → close)
- A named technique library (box breathing, physiological sigh, 5-4-3-2-1 grounding, progressive tension release, "name it to tame it," boundary-setting scripts) so responses stay concrete instead of generic
- A hard crisis-override: if the person signals self-harm or crisis, the assistant stops offering techniques and redirects to real support
- Explicit constraints against diagnosing, claiming clinical credentials, or giving medication advice
- A word-count discipline (~120 words) to respect that the user has minutes, not an hour

## The app

- **Two-panel layout**: chat on the left, a live "breathing companion" panel on the right with a circle that pulses ambiently and shifts into a guided 4-7-8 breathing rhythm (with timed text cues) when tapped — so the "quick technique" promise is visible in the UI itself, not just described in text.
- **Sage + amber palette** instead of a clinical blue/white pairing, to feel like a supportive colleague's office rather than a medical tool.
- **Full API wiring**: calls `api.anthropic.com/v1/messages` with `claude-sonnet-4-6`, sends full conversation history, and handles loading states, invalid/missing API keys, rate limits, and network failures gracefully.
- **Empty state** with four starter-scenario chips (racing thoughts, inbox chaos, can't switch off, tense conversation) to lower the barrier to the first message.
- **Collapsible "How this was built" panel** with tabs for the system prompt, UI decisions, and future extensions (calendar-aware tools, memory of which techniques worked, weekly reflection workflows).

## Key learnings

- **Scoping the system prompt narrowly made the assistant more useful, not less.** Telling it to offer exactly *one* technique (not a menu) and cap responses at ~120 words produced tighter, more actionable replies than a general-purpose wellness prompt would have.
- **Safety can't be an afterthought in a wellness bot.** Writing the crisis-handling instructions as a hard override — not a soft suggestion — was the most important part of the prompt, even though it's the least likely to trigger in most sessions.
- **The UI can demonstrate the product's promise, not just describe it.** Putting a real, functioning breathing guide next to the chat (rather than only having Claude describe breathing steps in text) made the "quick technique you can use right now" outcome tangible.
- **Interview-first prompting produces better-scoped outputs.** Answering structured MCQs before generation (audience → outcome → input style → output format → tone) meant the system prompt and UI were aligned to a specific persona instead of a generic "wellness chatbot."
- **Client-side API key handling needs to be explicit about trust.** Since this is a single HTML file with no backend, showing the user clearly that the key lives only in tab memory (never localStorage, never persisted) was necessary for a product like this to feel trustworthy.
