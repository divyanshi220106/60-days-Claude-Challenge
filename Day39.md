# Day 39: PDF Splitter & Merger – Client-Side Web Application

## Project Title

**PDF Splitter & Merger**

## Overview

Built a premium single-page interactive PDF utility application that allows users to split and merge PDF documents directly in the browser without uploading files to any external server.

The application was designed with a focus on modern UI/UX, privacy, performance, and offline-friendly client-side processing.

## Objective

The goal of this project was to create a professional PDF management tool similar to commercial PDF utilities while keeping all processing completely inside the user's browser.

## Features Implemented

### PDF Splitter

* Upload PDF files through file selection or drag-and-drop.
* Automatically detect total number of pages.
* Generate visual page thumbnails for document preview.
* Preview PDF pages before processing.
* Multiple splitting methods:

  * Split by specific page numbers.
  * Custom page ranges.
  * Split after selected pages.
  * Split every N pages.
  * Extract selected pages into new PDF files.
* Support multiple split ranges in a single operation.
* Validate page ranges and highlight invalid inputs.
* Preview output document structure before generating files.
* Download processed PDF files.

### PDF Merger

* Upload multiple PDF files.
* Drag-and-drop file uploading.
* Display uploaded PDFs with:

  * File names.
  * Page counts.
  * Visual previews.
* Reorder PDFs using drag-and-drop.
* Show:

  * Total number of files.
  * Total page count.
  * Expected merged output details.
* Generate and download merged PDF.

## Technical Implementation

### Technologies Used

* HTML5
* CSS3
* JavaScript
* PDF processing libraries:

  * PDF.js for PDF rendering and previews.
  * PDF-lib for PDF creation and manipulation.

## Key Features

* 100% client-side PDF processing.
* No backend server required.
* No external file uploads.
* Privacy-focused architecture.
* Responsive design for different screen sizes.
* Dark mode support.
* Smooth animations and micro-interactions.
* Accessibility-friendly UI.
* Loading indicators and error handling.
* Offline-friendly after initial loading.
