# Day 46 — Autonomous Agent Studio

Building a real multi-agent orchestration pipeline that plans, executes, evaluates, critiques, improves, and remembers — live against the Claude API — until it hits a genuine stop condition.

## What I built

**Autonomous Agent Studio**: a single-page HTML app that runs a live 8-agent pipeline for social media ad copy (Instagram + Facebook + LinkedIn variants) for a given brand brief.

**Agents in the pipeline:**

| Agent | Job |
|---|---|
| Planner | Turns the brief into a per-platform strategy (hook angle, tone, key message) |
| Executor | Writes the first full draft ad set from that strategy |
| Evaluator | Scores the current draft 0–10 (persuasiveness, clarity, brand fit) — every round, live |
| Critic | Turns the score into concrete, actionable weaknesses per platform |
| Improver | Rewrites the draft to address those weaknesses, given full round context |
| Memory Manager | Condenses each round into a running log so later rounds don't repeat fixes |
| Safety Monitor | Flags unsubstantiated claims / platform-policy risk (advisory, non-blocking) |
| Final Reviewer | One last polish + QA sign-off once a stop condition fires |

## Why it's a real loop, not a fixed sequence

- The improvement cycle is an actual `while(true)` loop in JS — Evaluator → Critic → Improver → Memory Manager, then back to Evaluator — with a genuine `fetch` call to `api.anthropic.com/v1/messages` every single pass. No canned scores, no scripted text.
- **No preset round count.** The loop only ends when a stop check fires, checked in this order every round:
  1. **Plateau** — score improved less than 0.3 for 2 straight rounds
  2. **Threshold** — score crosses the target set at launch (default 8.5/10)
  3. **Hard cap** — a fixed iteration ceiling, but only as a safety fallback, never the intended ending
- Every score, critique, and reasoning string shown in the UI is the literal text from that round's model response — nothing is faked or interpolated.
- State threads forward explicitly: each Improver call receives the prior round's Evaluator score + reasoning, the Critic's weaknesses, and the full memory log. Each Evaluator call receives the current draft plus that same memory context.

## Dashboard

- Live agent roster with an active/done state per agent
- An animated SVG diagram of the actual cycle — Improver loops back to Evaluator, with a separate branch to Final Reviewer that only lights up once a stop condition fires
- Round indicator reads "Round 3 — checking stop condition…", never "Round 3 of 5"
- Live score bar, per-round evaluation/critique/safety reports, activity log terminal, round-over-round history with deltas
- Final summary naming the exact stop reason, execution stats (rounds run, total improvement, API calls, retries handled), and an agent performance summary

## Key learnings

- **Making the stop condition a runtime result, not a design decision, changes the architecture.** The temptation is to just loop `for i in range(5)` — forcing an actual plateau/threshold check meant building real delta tracking and a consecutive-streak counter, not just an if-statement.
- **Structured JSON contracts per agent are what make a multi-agent pipeline reliable enough to render live.** Every agent's system prompt demands JSON-only output matching an exact schema; without that, gluing 8 sequential model calls together in a UI would be far more fragile.
- **Threading memory forward is easy to under-build.** It's tempting to just re-send the whole draft history each round; a dedicated Memory Manager agent that *summarizes* what's already been tried keeps later Improver calls from repeating ineffective fixes without blowing up the prompt size.
- **Advisory agents (Safety Monitor) shouldn't block the loop.** Keeping it non-blocking but still surfaced in the dashboard was a deliberate design choice — it flags risk without letting a false-positive stall the whole pipeline.
- **Calling the live API directly from a saved local HTML file is the sharpest edge case.** Inside Claude's own artifact sandbox the `fetch` works with no key; opened as a plain local file it needs a key/proxy wired in — worth calling out explicitly rather than letting it silently fail.

## Extension ideas

- Human-in-the-loop approval gate before Final Reviewer
- Three independent Evaluator passes averaged per round, to reduce single-call scoring variance
- A Router agent that decides which of the 8 agents a given brief actually needs
- Persistent brand memory across campaigns via local storage
- Tool-using agents (e.g. Planner with web search for competitor ad research)
