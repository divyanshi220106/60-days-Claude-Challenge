# Day 37 — Task Compass: Organizational Thinking Simulation

## Overview
Today's exercise used a single, self-contained prompt to generate **Task Compass**, an offline HTML/CSS/JavaScript simulation game that teaches ownership, delegation, escalation, and collaboration inside a real organization — rather than testing job titles directly.

**Workplace explored:** Healthcare (Hospital)

**Roles modeled:** Nurse (RN), Physician, Pharmacist, Lab Technician, Care Coordinator, Hospital Administrator, Health IT / Informatics, Patient Access / Front Desk

## What the App Does
- **Stage 1 — Who Owns This?**: Drag-and-drop a role into an ownership slot for a real workplace scenario (e.g., a medication dosage mismatch), then see the primary owner, the reasoning, and which roles typically assist.
- **Stage 2 — Task Routing**: Build the correct multi-step path a task travels through the organization (e.g., Physician → IT → Pharmacist → Nurse for a new prescription).
- **Stage 3 — Collaboration Challenge**: For larger situations (e.g., a patient-satisfaction drop or an outbreak response), select up to four roles and mark the lead, then compare against a primary owner + supporting-team answer with a communication-flow explanation.
- **Dashboard**: An SVG radar chart scores four categories — Ownership, Delegation, Collaboration, Workflow Thinking — followed by a written reflection on strengths, tendencies to over-assign responsibility, and places collaboration was underestimated.

## Key Learnings
- **Ownership isn't always the "closest" person.** Several tickets (e.g., a missing EHR order, a call-button outage) look like a nurse's or physician's problem on the surface but actually belong to Health IT — ownership follows accountability, not proximity.
- **Workflows have a logical order for a reason.** Routing a prescription through Physician → IT → Pharmacist → Nurse isn't arbitrary — each handoff exists to catch a different kind of error before it reaches the patient.
- **Complex problems resist single-owner thinking.** Scenarios like a hospital-wide satisfaction drop or an outbreak response genuinely need 3–4 roles involved; picking just one "owner" under-represents how real coordination works.
- **Designing the reveal logic mattered as much as the questions.** Explaining *why* an answer is correct (not just marking it right/wrong) was the actual teaching mechanism — the game is a vehicle for that reasoning, not a quiz.
- **Heuristic scoring can still be meaningful.** Turning drag-and-drop choices into four named categories (via simple overlap/position math) was enough to produce a personalized, non-judgmental reflection rather than a raw score.

## Reflection
Building this reinforced that most real workplace friction isn't about not knowing who's "supposed" to do something — it's about under-communicating handoffs and defaulting to a single owner when a problem is actually cross-functional. Task Compass tries to make that visible in a low-stakes, game-like way instead of a lecture.
