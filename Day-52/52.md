# Day 52 — System Design

**Project:** StudyNotes AI
**Phase:** Day 2 of 10-day capstone (AB Talks 60-Day Claude AI Challenge)

## What I did today

Turned the Day 1 PRD and Implementation Blueprint into a complete technical blueprint — no production code written, per the Day 2 rules.

## Tech stack finalized

- **Frontend:** React (Vite) → Vercel
- **Backend:** Node.js + Express → Render
- **Database & Auth:** Supabase (PostgreSQL + Google OAuth)
- **AI:** Claude API (Anthropic)
- **ORM:** Prisma
- **File handling:** multer (uploads) + pdf-parse (PDF text extraction)

Chose Supabase for both database and auth to cut setup work — one dashboard, Google OAuth largely pre-wired, generous free tier.

## Design work completed

- **System architecture** — component diagram, data flow, request lifecycle, AI interaction, and external services, all in Mermaid
- **Database schema** — `users`, `notes`, `summaries` tables, validated against every PRD user story
- **API design** — every v1.0 endpoint (health check, notes, summarize, summaries CRUD) with request/response/validation/auth/error cases, no implementation
- **UI & user flow** — user flow diagram, screen flow, low-fidelity wireframes for all 5 screens, navigation rules
- **Project structure** — full folder layout for frontend and backend, with a day-by-day map of which folders get touched when

## Key learnings

- Designing the database schema against every PRD user story *before* writing code catches gaps early (e.g., confirming `note_id` needed to be nullable so deleting a note never destroys a saved summary).
- Isolating the AI call into a single backend service file, separate from prompt templates, keeps the system flexible if the AI provider or prompt strategy changes later.
- A clear day-by-day "which folders get touched" map removes any ambiguity about where Day 3+ code should live.
