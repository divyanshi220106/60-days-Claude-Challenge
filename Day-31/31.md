# Day 31 — AI Supply Chain Control Tower

## 🎯 Challenge

Build a fully interactive, single-file HTML/CSS/JS simulation game that puts the player in the role of **Head of Operations** at a global supply chain company — reacting to live disruptions, making trade-off decisions under time pressure, and managing a dashboard of real operational KPIs.

## 🛠️ What I Built

An **AI Supply Chain Control Tower** — a dark-themed, logistics-style dashboard game contained entirely in one `control-tower.html` file (HTML + CSS + vanilla JS, no frameworks, no libraries, works fully offline).

**Core features:**
- 8 live KPIs: Service Level, Customer Satisfaction, Inventory Health, Transportation Efficiency, Operating Cost, Revenue Protected, Score, and a 3-minute countdown clock
- 10 randomized alert types (port congestion, supplier delays, truck breakdowns, stockouts, customs holds, demand spikes, machine failures, weather disruptions, inventory miscounts, damaged shipments)
- Each alert carries its own priority, countdown timer, business impact tags, and 3–4 tailored action buttons with genuinely different consequences (best / good / weak / ignore / delay)
- Alert frequency ramps up as the clock runs down, forcing multiple simultaneous incidents late in the shift
- A live scrolling event log, toast notifications, pause/resume, sound toggle, and help modal
- End-of-shift debrief: final score, letter grade (A+ to D), KPI recap, correct vs. wrong decision count, and a written performance summary

## 🧠 Key Learnings

1. **Prompt structure drives architecture.** Breaking the brief into explicit sections (theme, gameplay, KPIs, alert types, actions, game logic, difficulty, visuals, end-of-game) mapped almost 1:1 onto clean JS modules — config/data, state, KPI rendering, alert lifecycle, logging, timers, and end-game scoring. Well-structured prompts produce well-structured code.

2. **Consequence design matters more than visuals.** The hardest part wasn't the CSS glow effects — it was making sure every action button had a *meaningfully different* trade-off (cost vs. speed vs. risk) so decisions actually felt like decisions, not flavor text.

3. **Delayed consequences add real tension.** A "Delay Decision" action that resolves 3–5 seconds later — good or bad — turned out to be the single mechanic that best simulated real operations, where you rarely know immediately if a call was the right one.

4. **Single-file constraints force discipline.** No frameworks, no external assets, everything offline — this pushed toward vanilla JS state management and CSS custom properties instead of reaching for a library, and the result is easier to read, ship, and hand off.

5. **A control-tower aesthetic needs restraint.** Dark background, cyan/blue highlights, and priority-coded red/orange/blue alerts communicate "ops center" instantly — but only if animation (pulse dots, scanning bars, flash states) is used sparingly on the moments that matter (critical alerts, KPI changes), not everywhere.
