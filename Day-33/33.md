# Day 33 — Media Integrity Analyzer

## What I built
A single-file, offline HTML app that teaches media literacy through guided discovery instead of a quiz. It runs two challenges:

- **Headline Detective** — read a fictional headline + article, flag the exaggerated words, guess whether you'd click it, then reveal a Headline Accuracy Score, the exact phrases that don't match the reporting, and a fair rewrite.
- **Emotion Detector** — read a fictional social post, flag the words doing emotional work, name how it made you feel, then reveal the target audience, the manipulation technique, and a neutral rewrite.

A live metrics bar (Headline Accuracy, Source Reliability, Emotional Manipulation, Audience Targeting) updates as each challenge resolves, ending in a Media Integrity Dashboard with an overall score, the session's biggest red flag, and three practical habits. A replay button pulls new randomized scenarios each time.

**Stack:** vanilla HTML/CSS/JS only — no frameworks, no backend, no external assets. Works fully offline.

## Key learnings

1. **Show, then tell.** The biggest design shift was moving from "explain the concept, then test you" to "let you react first, then reveal why you reacted that way." Letting people click the exact words that fooled them made the lesson land in a way a definition never would.
2. **Specificity beats abstraction.** Instead of a generic "misinformation score," tying every reveal to the literal phrase in the literal headline ("'Poisoned'" vs. what the article actually says) made the pattern recognizable and transferable to real content.
3. **Design should reinforce the metaphor.** Framing the app as a case file — exhibits, a stamp reveal, a dossier tracker — wasn't just decoration; it matched the actual task (investigate, don't just consume) and made the interface easier to navigate.
4. **Randomized content pools matter for replay value.** Building 4 headline scenarios and 4 emotion scenarios (instead of 1 each) meant the "Replay" button teaches a genuinely new lesson each time, not just a repeat.
5. **A single HTML file is a surprisingly capable constraint.** No build tools, no npm, no APIs — just CSS custom properties for theming, `conic-gradient` for the score dials, and vanilla JS for state. Good discipline for keeping scope tight.
