# Day 34 — Marketing Detective

An AI-generated, single-file HTML "detective game" that teaches marketing mistakes through fictional case investigations.

## What I built

A self-contained `marketing-detective.html` app — no frameworks, no CDN, no backend — that runs entirely offline in a browser. Prompted Claude to act as a frontend developer, UX designer, and marketing strategist to design the whole experience end to end.

**Flow:** Choose a color theme → get assigned a case file → investigate evidence on a corkboard (metrics, customer comments, social sentiment, clues) → name the primary marketing mistake → get a "Case Closed" verdict → review a full Learning Report → replay with a new randomized case.

**Under the hood:**
- Vanilla HTML/CSS/JS (Claude auto-switched away from React+Babel CDN to guarantee the file runs reliably standalone, offline, from disk)
- 12 detailed fictional marketing cases stored in a JS array, each with objective, audience, channels, budget split, campaign metrics, customer comments, social performance, a primary mistake, 3 supporting clues, explanation, and improvements
- Custom pointer-based drag-and-drop for evidence cards (no library)
- Dark corkboard/case-file aesthetic: paper textures, push pins, brass folder clips, glowing accents tied to the selected theme
- 5 selectable color themes, including Claude Orange

## Key learnings

- **Constraint-driven prompting works well.** Telling Claude exactly when to fall back from React/Babel to vanilla JS (i.e., if it would hurt standalone reliability) produced a more robust deliverable than defaulting to a framework.
- **Structured data in the prompt = structured output.** Specifying the exact fields every case needed (objective, audience, channels, budget, metrics, comments, social, mistake, clues, explanation, improvements) made the generated cases consistent and genuinely useful for learning, not just filler text.
- **Game framing changes how marketing concepts land.** Turning "common marketing mistakes" into an investigation with evidence and a verdict made abstract concepts (audience-channel mismatch, ad fatigue, broken funnels, tone-deaf localization) much easier to internalize than a static article would.
- **Self-verification matters.** Asking Claude to internally check for syntax/runtime errors before returning the file avoided the classic "looks right but breaks on open" problem with single-file HTML deliverables.
