# Day 50 — Defend Your Experience

An AI-powered mock cross-examiner that stress-tests every claim on your resume before a real interviewer does.

## The problem

Most interview prep tools polish your resume. None of them test whether you can actually *defend* what it says under pressure — the follow-up question, the "walk me through exactly how," the "what would you have done differently."

## What I built

A single self-contained HTML file (vanilla HTML/CSS/JS, no backend) that:

- **Interviews you first.** Before touching your resume, it asks what you're defending, what kind of interviewer you're worried about (technical / behavioral / executive / mixed), and how tough to be — all via one-question-at-a-time MCQs.
- **Extracts your claims as evidence.** Upload or paste a resume, and Claude turns it into an "Exhibit Ledger" — 6–10 concrete claims (achievements, metrics, ownership, leadership) pulled from your own words, not a generic template.
- **Cross-examines you live.** One question at a time, generated from your actual answers, going deeper the vaguer you are and moving on once you've genuinely defended a claim. Every question is personalized — no canned interview bank.
- **Scores confidence per claim in real time.** A live meter (weak → needs work → well defended) updates after every exchange.
- **Generates a Defense Report.** Overall readiness score, per-exhibit verdicts, and specific coaching notes referencing what you actually said — plus a one-click re-examination of just the weak spots.

## Design

Went with a minimal, calm aesthetic — off-white paper background, a serif/sans pairing (Fraunces + Inter), and a "legal exhibit" metaphor (Exhibit A, B, C…) as the structural device, since the whole app is literally about building a defense. No dark-mode gradient clichés, no cream-and-terracotta default — just quiet, deliberate spacing with one accent color (slate blue) standing in for "the examiner."

## Tech

- Single HTML file, no build step, no backend
- Calls the Anthropic Messages API (`claude-sonnet-4-6`) directly from the browser, inside Claude's artifact environment
- Structured JSON responses for claim extraction, question generation, and report synthesis
- LocalStorage for session history, retry/backoff for rate-limit errors, drag-and-drop upload, .txt export

## Key learnings

1. **Interviewing the user before generating anything produces a dramatically more tailored artifact** than jumping straight to code — the MCQ wizard pattern (one question, immediate branching) is worth reusing elsewhere.
2. **Single-call turn design matters for latency.** Combining "evaluate the last answer" + "decide whether to move on" + "ask the next question" into one JSON-structured API call kept the interview feeling responsive instead of laggy.
3. **A metaphor can double as UI architecture.** Treating each resume claim as an "exhibit" wasn't just flavor text — it justified the numbering system, the ledger sidebar, and the report structure all at once.
4. **Graceful degradation is part of the product, not an afterthought.** Rate-limit handling with exponential backoff and a visible retry banner turned "the API hiccupped" from a dead end into a one-click recovery.
